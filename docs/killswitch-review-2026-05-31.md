# 안전 브레이크(킬스위치) 검토 + 개선 방안 (2026-05-31)

> 읽기 전용 조사 결과와, 그에 따른 개선 방안입니다. **코드는 아직 안 바꿨습니다.**

## 1. 기록 — 무엇을 발견했나

### 발견 ① 킬스위치는 "고장"이 아니라 **그물코가 너무 크다**
킬스위치는 `오늘 평가금액 / 오늘 아침 평가금액 − 1 ≤ −3%` 일 때 발동합니다
(`risk/manager.py:248-253`). 그런데 계좌가 약 **4,897만원**이라, 손실을 %로 보면:

| 날 | 손실 | 계좌 대비 |
|---|---|---|
| **5/12** | −448,396원 | **−0.92%** |
| 5/26 | −2,582원 | −0.005% |
| 5일 누적(순) | −374,419원 | −0.76% |

→ **−3% 발동에는 하루 약 147만원 손실이 필요**합니다. 최악의 날(5/12)도 −0.92%라 근처도
못 갔습니다. **심지어 −1% 로 낮춰도 5/12(−0.92%)를 못 잡습니다.** 즉 이 봇은 하루 3%씩
무너지는 게 아니라 **0.5~0.9%씩 비용으로 야금야금 새는** 방식이라, 계좌 단위 %-킬은 구조적으로
이 실패 모드를 못 잡습니다.

### 발견 ② "조용히 꺼지는(fail-open)" 설계
`should_force_liquidate` 는 평가금액 기준(day_start_equity)이 없거나 0이면 **경고 없이 그냥
False(=청산 안 함)** 를 반환합니다(`manager.py:250-251`). 안전장치가 자기 입력을 못 읽을 때
**알람을 울리는 게 아니라 조용히 손을 놓습니다.**

### 발견 ③ 5/12 당일은 계좌 스냅샷 자체가 없었다
5/6~5/14 리포트엔 잔고/평가금액 기록이 통째로 없습니다(스냅샷 미생성 → day_start_equity 없음).
그래서 그날 킬스위치는 발견②에 의해 조용히 비활성. **5/22부터는 스냅샷이 생겨 이 구멍은 해소.**

### 발견 ④ 리포트의 `closing_equity=0` 은 미관 문제일 뿐
리포트는 키움 원본 필드 `total_evaluation`(청산 후엔 0)을 표시합니다(`daily.py:410`). 하지만
**킬스위치가 쓰는 봇 내부 평가금액은 `예수금+보유평가`로 제대로 계산**됩니다
(`runner/__init__.py:404-405`). 즉 **모의 모드에서 평가금액 추적은 정상** — 표시 숫자만 엉뚱한
필드를 골랐을 뿐(별도 미관 수정 후보).

## 2. 개선 방안

### 🟢 개선 A (구현 완료) — "조용히 꺼지지 말고 **자동으로 안전하게**" (fail-safe + 알림)
- **무엇:** `daily_loss_kill` 이 켜져 있는데 평가금액 기준을 못 읽으면(day_start_equity ≤ 0):
  1. **새 매수(진입) 자동 차단** — 사람 대응 없이 위험 비축(fail-safe). 보유분 손절·트레일링·
     15:15 청산(SELL)은 그대로. 평가금액 복구 시 자동 진입 재개.
  2. **텔레그램 경고 1회** — "⚠️ 안전 브레이크 작동 불능…"(스팸 방지 1회).
- **왜 알림만으론 부족한가(2026-05-31 사용자 지적):** 일과시간엔 사용자가 텔레그램을 못 봐
  대응 불가 → 봇이 **스스로** 위험을 줄여야 한다. 그래서 fail-loud(알림)에서 fail-safe(자동
  진입 차단)로 격상.
- 👍 사람 없이 동작·보수적·과반응 없음(보유분은 정상 보호)·복구 시 자동 재개.
- 👎 5/12 같은 "작은 %" 손실 자체는 여전히 개선 B 영역(촘촘한 그물).
- **구현:** `risk/manager.py` `kill_switch_baseline_missing`(순수) + `runner/__init__.py`
  매수 게이트 차단(`runner.buy_blocked_kill_switch_blind`) + `_check_kill_switch` 1회 경고 +
  `notify/{telegram,throttle}.py` 메시지·즉시푸시. 단위테스트 추가, 전체 1,129 통과.

### 🟡 개선 B (검증 후) — churn 에 맞는 더 촘촘한 브레이크
계좌 %-킬이 못 잡는 "비용으로 새는 나쁜 날"을 겨냥. **단 임계는 5일 표본에 맞추지 말 것**
(과적합 — −1%냐 −0.8%냐로 5/12 포함 여부가 갈림). 후보:
- **B-1 일일 순실현손익(비용 차감) 하한:** 그날 비용 차감 실현손익이 −X 아래로 가면 신규 진입
  중단. "그날 전략이 틀렸다"를 손익으로 직접 감지(킬스위치보다 본질).
- **B-2 일일 비용/회전 상한:** 그날 누적 추정비용 또는 거래대금이 상한 초과 시 신규 진입 중단.
  (단 제3자 검토: 단순 *건수* 캡은 승자도 자름 → *비용* 기준이 더 안전.)
- **공통 전제:** 라이브 전 `analyze_trades.py` 류 **ledger 리플레이로 검증** + 임계는 며칠
  **shadow 관측으로 forward 설정**. "재앙 차단" 용도이지 수익 최적화가 아님.

### 🔴 하지 말 것
- −3% 킬을 근거 없이 −1%/−0.8% 로 낮추기(5일 노이즈에 임계 끼워맞춤).
- 승자까지 자르는 거래 *건수* 캡(이미 제3자 검토에서 해롭다고 정량 확인).
- 평가금액 추적을 "고치겠다"며 정상 동작하는 내부 계산을 건드리기(미관 필드만 별도 정리).
